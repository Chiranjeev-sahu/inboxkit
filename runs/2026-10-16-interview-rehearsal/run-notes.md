# Fresh-checkout natural-language interview rehearsal

Date: 2026-10-16. Goal: test whether an independent Codex process can open a fresh local clone, accept a new ICP in ordinary language, and produce two new sourced and verified draft contacts. This is an execution test, not part of the 100-row agency campaign.

The clone started from commit `f99c8d8`. A local ignored `.env` was copied into it as the documented credential prerequisite. The prompt supplied a new ICP: B2B cybersecurity software vendors with an existing internal SDR/outbound team and an active outbound-growth hire. It requested two decision makers, sources, verified work emails, first lines, and draft exports, with existing credits only and explicit authorization for those two prospects' lookup data to reach the user's providers. It also told the agent not to reuse prior companies or silently relax the rule. No special slash command or skill name was used in the prompt.

The independent `codex exec --approve-for-me` process read the repository instructions, separated company fit from hiring signal, searched public sources, and identified two plausible company/buyer candidates. It did **not** create accepted lead rows or an export. Its normal shell tool failed to launch with `helper_unknown_error: setup refresh had errors`; it used another available tool to continue reading. The project-scoped hosted MCPs reported missing OAuth/API authentication for some providers. The direct Icypeas/BounceBan API route was unavailable in that CLI environment. The agent then tried connected Lusha tools: one `contacts_search` completed, but a subsequent lookup was stopped before execution because automatic approval review could not run after the Codex account hit its usage limit. The CLI exited with code 1. The stated review failure was due to usage limit, **not** a judgment that the action was unsafe. We did not bypass the review or retry paid usage.

Result: **0 completed contacts, 0 verified email rows, 0 new draft exports.** The agent's source screening and instruction routing started correctly, but this test does not demonstrate a reliable end-to-end fresh-checkout run. Whether the completed Lusha search used an included credit was not established by the truncated CLI output; recheck account usage before another provider test. The temporary clone and copied `.env` were removed after the run. The original repository and its agency campaign outputs were unchanged, apart from this documented test and project status notes.

Before claiming interview readiness, repeat a small natural-language rerun in the actual Codex app session that will be used for the call, with provider connections authenticated, credits checked, and enough Codex usage available. A successful test must produce at least one sourced contact and an audited draft export from that fresh session; log any shortfall honestly.

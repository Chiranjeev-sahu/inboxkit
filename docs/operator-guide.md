# Operator guide

Run commands from the repository root. Python 3.9+ is sufficient; all checked-in scripts use the standard library. Research is performed by Codex or Claude Code following [AGENTS.md](../AGENTS.md), [CLAUDE.md](../CLAUDE.md), and the [runbook](../skills/lead-research/SKILL.md).

## Setup

1. Clone the repository and open that folder as the agent's project. Check `python --version`. On Windows, `py -3` can replace `python` if that is your installed launcher.
2. Create `.env` only if needed: `if (!(Test-Path .env)) { Copy-Item .env.example .env }` in PowerShell. Fill the fields for your chosen providers without printing or committing their values.
3. Choose a working research tool, a named-email finder and a verifier. One provider may perform more than one role. Every provider in `.env.example` is optional; this is not a requirement to open fourteen accounts.
4. Direct API calls read local keys privately. Hosted MCPs use the operator's authentication; a key in `.env` does not log them in. [MCP connection notes](mcp-setup.md). Only authenticate routes you intend to use.
5. Start with a small requested count in normal language. The agent states company fit, operational signal and buyer rules, checks commercial suitability, then researches. [Example prompts](../README.md#natural-language-requests).

For example, agent web search plus funded Icypeas discovery/verification can cover a small run using `ICYPEAS_API_KEY` and matching `ICYPEAS_ACCOUNT_EMAIL` for balance checks. Datagma plus BounceBan is another previously tested combination. These examples establish possible roles, not guaranteed results or a fixed ranking. Check current capacity before calls.

## Check access before a research run

- Confirm the project is trusted and the intended web/provider tools are present in the fresh chat.
- Check the account balance and the specific endpoint needed. A balance response does not prove enrichment permissions.
- Use existing credits only. Bound any diagnostic sample, record provider debits and stop after a clear result. Connector-specific confirmation requirements still apply.
- Run `python -m unittest discover -s tests -v` and `python scripts/check_submission.py` offline.
- Use the [project guide](../README.md#review-the-campaign) and the [new-ICP example](../runs/2026-10-18-b2b-saas-outbound-fresh/README.md) to identify the intended output. Keep `.env` private.
- Keep the user's current ICP and target count in the new run's inputs. Save partial work before switching providers or stopping.

## Export and refresh

### New ICP

The agent creates `runs/<run-id>/evidence/leads.csv`, judges its sources and writes the run README and draft messages. Replace `<run-id>` with the actual folder name:

```powershell
python scripts/prepare_export.py runs/<run-id>/evidence/leads.csv --output-dir runs/<run-id> --presentation
```

The command generates top-level `send-ready.csv` and `review-parked.csv`; `evidence/` holds `qualified.csv`, `excluded.csv` and `audit.json`. Review all three dispositions and compare facts with sources. The agent's summary and drafts are not generated by the mechanical script.

### More default-agency companies

The agent appends distinct-company attempts to `runs/2026-10-15-second-pass/leads.csv`, preserving the old rows, adding named greeting/variant fields where appropriate, and recording new batch evidence. It checks the entire accumulated dataset and public suppression before enrichment.

```powershell
python scripts/prepare_export.py runs/2026-10-15-second-pass/leads.csv
Copy-Item runs/2026-10-15-second-pass/qualified.csv deliverables/lead-sheet.csv
Copy-Item runs/2026-10-15-second-pass/send-ready.csv deliverables/send-ready.csv
Copy-Item runs/2026-10-15-second-pass/review-parked.csv deliverables/review-parked.csv
python scripts/check_submission.py
```

These copy commands refresh the intended existing submission snapshots. Review the audit before copying. Update the current status/count summaries after actual additions, and keep dated historical records intact. The checker reports actual counts; it does not invent contacts or erase holds. No additions are made by merely running an export.

### Demonstrate the gates without touching the submission

```powershell
python scripts/prepare_export.py demo/leads.csv --suppression demo/suppression.csv --output-dir tmp/demo-output
```

Open `tmp/demo-output/audit.json` and `excluded.csv`. They show invalid, duplicate and suppressed records plus review-only cases. The fixture is synthetic. No API calls or sending occur.

## Troubleshooting

| Symptom | Action |
| --- | --- |
| `python` is not recognized | Install/enable Python 3.9+ or use an existing `py -3` launcher. Do not assume the author's private runtime path exists. |
| New run has no `leads.csv` | Ask the agent to research the ICP first. The export script consumes researched rows; it is not a discovery engine. |
| Tool is listed but returns `Unknown tool` | Current chat/tool registration may be stale after a connection change. Reload the intended connection in a fresh project chat and test its free account endpoint. A 0-credit balance has not been established by this error. Use working fallbacks meanwhile. |
| HTTP 401 | Check that the key, account email and connected account match. Never log the key or credential-bearing URL. |
| Apollo `API_INACCESSIBLE` | Current connected Free-plan people/company discovery endpoints are denied. Skip them until access changes. Saved-contact search worked but does not discover new people; named-person/company enrichment remain untested. |
| HTTP 429 | Respect pacing, save state and retry later or use a suitable fallback. Repeated immediate requests are not a fix. |
| Balance is zero | Skip paid lookups on that account. A visible tool or daily request quota does not restore credits. |
| LinkedIn returns 999 or cannot be opened | Preserve the profile URL and corroborate identity with company-authored pages/posts and publicly indexed profile content. State the access limitation. |
| Verifier says only catch-all | Retain the raw result and try an available specialist when warranted. Preserve the separate domain flag; do not guess delivery. |
| Two clear verifier results conflict | Park as unknown with both results. An ambiguous catch-all response alone is not a clear negative. |
| Alternate email domain | Require public relationship proof before promotion. A positive verifier does not establish ownership. |
| Too few qualifying companies | Keep the rule and show rejected/uncertain attempts. Explain the shortfall before proposing a rule change. |
| `Conflicting accept-all fields` | Resolve `is_accept_all` versus `verification_accept_all` in the source row using receipts. The exporter refuses to silently choose. |
| Message placeholder has no field | Complete the explicit [merge mapping](data-dictionary.md#merge-fields). Do not send blank or full-name-as-first-name merges. |

## Safe reruns and limits

Rerun the export after changing source rows or suppression; the generated CSVs are snapshots and will be replaced. Keep evidence in input rows and dated receipts. To compare without overwriting a run, use `--output-dir tmp/<comparison-name>`.

No automatic provider scheduler, persistent discovery database or live opt-out inbox exists. Resume and provider decisions are agent-led. The mechanical gate checks fields and holds; the agent judges evidence. A passing local check does not establish arbitrary-ICP yield, independent-machine authentication, actual delivery or campaign conversion.

All output remains draft. See the [reply opt-out procedure](opt-out-and-suppression.md) for the suppression gate and requirements for any separately authorized live campaign.
